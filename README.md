# attention-theme-engine

> **注意力机制**研究框架的**公开脱敏切片**：三级题材分类体系（行业 / 赛道 / 核心逻辑）+ 可解释规则引擎 + 关键词注意力权重迭代 + 无效信号过滤。
>
> ⚠️ **本仓库不是生产系统**。它是一套**独立可运行的最小实现**，用来公开方法与算法。
> 生产系统的完整概念集、原始数据源接入与商业逻辑不在公开范围内（见 [`docs/SLICE.md`](docs/SLICE.md)）。

MIT 开源 · Python ≥ 3.9 · 运行时零第三方依赖。

---

## 三层结构

```
① 题材体系   taxonomy.py + data/taxonomy.json
   行业 → 赛道 → 核心逻辑（题材）三级分类
   每个题材带一句「为什么它会动」（逻辑），不是一个标签

② 规则引擎   rules.py
   关键词规则 + 注意力权重 → 可解释打分
   每次打分都能回答：命中了哪些词？每个词贡献多少分？为什么拒绝分类？

③ 注意力迭代 attention.py
   分类错了不只记一笔账 —— 把注意力挪到正确的词上
   误判词的权重下调、正确词的权重上调，权重被夹在区间内不会跑飞
```

## 跑起来

```bash
git clone https://github.com/RewFa-CEO/attention-theme-engine.git
cd attention-theme-engine
pip install -r requirements.txt

python3 -m pytest tests/ -q          # 26 个测试
python3 eval/evaluate.py --train 6    # 基线 vs 迭代后 + 每轮变化
python3 eval/evaluate.py --explain "算力租赁签约落地，智算中心上架率提升"
```

## 三个值得单独说的设计决定

**1. 拒绝比硬分类更重要。**
真实热点流里大量文本根本不属于任何题材 —— 硬给它贴一个标签，等于往下游灌噪声。
引擎有两条拒绝线：分数低于阈值（`below_min_score`）、第 1 名相对第 2 名优势不足（`low_confidence`）。
本仓库黄金集的 25 条负样本 **100% 被拒绝**，正样本 **0 误拒**。

**2. 归因必须能给人看。**
`engine.explain(text)` 输出每个关键词的**权重 × 区分度 = 贡献**，以及完整的行业/赛道/题材路径。
一个分类结果如果解释不了，它就不该进生产。

**3. 区分度按「这个词属于几个题材」摊薄。**
「配额」同时出现在稀土与氟化工，「铜」也跨多个题材 —— 共享词的区分度按出现次数摊薄（`1/df`），
专属词记满。这样权重迭代才有意义：共享词需要更强的证据才该赢。

**4. 匹配前归一化空白。**
中英文混排里空格是排版产物而非语义（`AI 眼镜` 与 `AI眼镜` 是同一个词）。不归一化就会静默漏命中 ——
这类 bug 在生产上表现为「某类样本莫名其妙永远分类不出来」。

## 目录

| 路径 | 内容 |
|---|---|
| `src/ate/taxonomy.py` | 三级题材体系的数据结构与加载 |
| `src/ate/rules.py` | 规则引擎：打分、归因、拒绝 |
| `src/ate/attention.py` | 注意力权重迭代与评估 |
| `src/ate/classify.py` | 分类结果结构 |
| `src/ate/dataset.py` | 黄金样本集读写 |
| `data/taxonomy.json` | 题材概念集（公开子集） |
| `data/golden.jsonl` | 黄金样本（74 正 + 25 负，含跨题材干扰样本） |
| `eval/evaluate.py` | 评测 CLI（基线 / 迭代 / 归因） |
| `tests/` | 26 个测试：层级完整性、打分口径、迭代方向、泛化、拒绝率 |
| `docs/SLICE.md` | 切片边界与不公开的部分 |

## 怎么把新的题材加进来

1. 在 `data/taxonomy.json` 里加一条：三级路径 + 关键词 + 一句核心逻辑；
2. 在 `data/golden.jsonl` 里加几条样本（**至少一条跨题材干扰样本** —— 真实标题常常同时提两个题材）；
3. `python3 eval/evaluate.py --train 6` 看权重往哪挪；
4. `python3 -m pytest tests/ -q` 确认没把别的题材带歪。
